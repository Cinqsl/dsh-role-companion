# DSH 角色伙伴

此组合包面向 DSH `0.2.1-rc.2` / `0.2.1-rc.3` 的 Web / Desktop 设置页，同时在插件页保留入口。rc.2 支持角色之家、官方模型对话、QQ 文字收发和运行规则；文件工具仍要求 rc.3，并在 rc.2 上失败关闭。当前交付 owner 角色面板、角色之家创建/接入、版本化核心与规则、面板来信持久接纳，以及原生官方模型文字往返、受控资料与官方 Search/Fetch、指定 QQ 好友文字接收与回复，以及有来源的本地经历检索。Home 已打开与执行就绪分别显示。有来源的知识提议、纠正与回退，以及明确唤醒的自主内部活动和休息已启用；周期唤醒、活动预算、暂停、免打扰和主动联系遵守对应运行规则。

包内包含 Host、`cordis.patch.yml`、预构建 `./client`、生成的 `./typert` 和 `./remote`。不需要在用户 profile 中编译源码。缺少客户端或编解码产物、DSH 版本不符时拒绝激活并显示恢复步骤。

在目标载体的「插件」页安装本地 tarball 并启用组合包，然后打开组合包详情中的「角色面板」。Web 和 Desktop 分别使用各自载体的插件管理入口；普通 CLI 不管理保留的 Desktop profile。

「生命周期与迁移 → 自动更新」可开启对 `Cinqsl/dsh-role-companion` 固定 `main` 分支的周期检查。Host 只接受从 `git ls-remote` 读到的 40 位 commit；配置不接受任意仓库或分支，检查周期为 5 至 1440 分钟，默认关闭。发现新版本后排队一个后台更新进程，等 DSH 正常退出再通过 pnpm 安装 `git+https://github.com/Cinqsl/dsh-role-companion.git#<commit>&path:packages/companion`；也可以点击「立即更新并重启」，由 macOS DSH 的正常退出流程关闭应用，安装成功后自动重新打开。安装失败恢复原 `package.json` 与锁文件，并仍会重新打开旧版本。运行中不替换加载代码，避免绕过本轮已核对的代码来源和文件工具权限。本地链接结算的 commit 不是 main 的祖先时只报告阻止原因，不自动覆盖可能有未合并改动的开发分支。

「已安装」「配置启用」「Host 装载阶段」和「角色就绪」分别显示。插件管理器报告的覆盖、需重启或失败保留各自含义。普通 DSH 工作 Session 不自动成为角色聊天；`/role` 仅提供打开面板的指引。

所有自有 Remote 方法在 Host 检查 Gateway 注入的 owner 身份。请求体中的 `actor`、普通命令的用户来源和 QQ 文字均不能取得管理能力。状态读取与关闭面板不启动模型或改变业务状态。

原生对话使用官方 `deepseek-official/deepseek-flash`，凭据由现有 SDK provider 按私密引用解析，面板不接收凭据值。provider 必须显式配置 `https://api.deepseek.com/anthropic`。输出值不能超过当前 SDK 可确认的 provider 配置范围；修改 provider 配置后角色停稳，重新启用插件后再次核对。同一凭据引用的值轮换在后续请求生效。用户回合默认最多 8 次模型预留、16 次工具预留、10 分钟和 4096 output tokens；失败、取消与预留后未派发都保留原计数。网页调用使用现有官方独立 API，另受同一 Home 网页预算与 Web 规则约束；模型参数不能更换目标凭据或传输端点。

模型重试规则由 Home 独立持久保存，默认同一逻辑操作最多自动重试 1 次、无 Retry-After 时等待 1000 毫秒。可明确设为 0 次关闭；仅暂时性网络、限流和服务端错误允许受控重试，每次重新核对原来源、剩余期限、当前规则与额度并新预留。提供方独立 retry 必须配置为 normal / maxRetries=0。等待不占管理控制队列；改值不清用量或延长原截止，已开始请求按原参数收尾。面板显示当前版本、有效上限、已预留、剩余与收费重试次数。

同步必需的标准压缩摘要与主请求共用本用户回合模型上限和输出上限，逐次保存完整尝试。只压缩本轮已闭合的模型工具调用与结果，完整核心与原始来信继续保留；无法安全压缩或额度不足时保留进度并显示失败，不新增免费收尾请求。当前兼容固定官方 Basic 压缩服务与已核对的模型流、恢复组合。默认 Web 从现有预设声明保留一个配置修订，只给角色安装受控压缩实例，不继承整个预设或其工具；Base 的唯一全局 Basic 也受支持。声明、默认预设选择或服务生命周期变化会关闭新准入，旧工作完成记录与 flush 后再释放修订；重新启用后核对当前配置。标题、回复后额外整理和未发行辅助请求未开放，不能借原用户 Session 取得额度。明确唤醒的自主内部活动使用同一 Home 的机会与窗口准入，不借用户回合免费续行。

`role_read` 从 Home 固定快照读取获准核心、输入、回复和完整工具经历；query 提供本地词法补查。普通回合按当前绑定、撤销状态和原始来源的依赖限制取材，显式历史核对由 owner 来信发行，模型的 JSON 或用途文字不能增加权限。旧工具结果、摘要或复述不能把已退出日常范围的来源重新激活。工具不取得 owner、磁盘路径或任意文件读取能力。

`role_file` 只提供 list、readText、writeText、mkdir、同 scope 的 move 和 remove。Home 权限簿分别管理 works、journal 和外部 grant 的只读/读写模式；profile 仅保存当前机器的物理目录映射。先保存 Home grant，再在 owner 面板明确绑定本机目录；清除映射不删除原 Home 经历，也不授权旧路径迁移到新机器。真正撤销 Home 来源权限后，旧文件结果及其派生回复退出普通 Context，owner 仍可核对完整历史。

保护先于授权：Home 正文、版本、索引、维护资料与备份，以及已核对的凭据、实际配置、加载代码和运行资料不能被外部父目录授权覆盖。只兼容已核对的固定官方模块及可证明的官方 launcher 来源；未知 embedding、预加载或不完整代码历史时文件能力不可用。官方 CLI 实际 --patch 文件纳入保护与检查点。Desktop 入口有静态兼容检查，但本票实际安装验证使用官方 CLI/Web；不据此声明所有载体通过。

本机 file-mapping owner 使用 SDK 原子 KV 保存仅用于拒绝的资料根和已验证 Home 物理身份，正常关闭会等待已登记保存。退役资料根不因服务停用、声明移除或新进程而恢复访问。新 profile 的 owner 首次创建/接入会把独立锚点与 Home 选择一并保存；旧格式缓存升级保留全部拒绝记录，并由 owner 核对。升级后检查点变化须经角色插件实际停用、再启用并完成公开重核，随后按原请求重核目录；启动完成本身不授予该权限。缺失、不可读写或未确认变化保持拒绝，不能以空缓存、清映射或失败编辑重置保护。

文件路径只能相对 scope，不能指定绝对 root、actor 或权限版本。根操作、父路径穿越、目标与父链符号链接、多硬链接、大小写/规范别名和受保护后代都会拒绝。写入必须提供 expectedTag 或 absent；移动限同 scope。目录删除和移动先完成有界树预检，超限时不开始修改。文件修改使用全角色独占屏障，只读沿用 Home 的并发配置；这是可信工具入口政策，不是操作系统沙箱。

FileRules 初始 UTF-8 正文上限为 1048576 字节、目录单页 200 项、递归预检 1000 项、合作期限 10000 毫秒，均可由 owner 版本化修改；后续新动作消费新值。模型展示上限复用独立读规则，完整原文和结果仍归 Home，截取展示不等于截断归档。工具不开放通用 shell、二进制读写或继承的官方文件工具。

独立读规则由 Home 持久保存，初始只读并发上限为 2、模型可见展示上限为 12000 个 Unicode 码点、合作期限为 10000 毫秒。面板修改作用于后续新工具准入，已开始动作按原参数收尾，旧预留和回合截止时间保留。展示最小值为 256 码点，以容纳完整资料引用；不兼容的值整笔拒绝。合作期限请求取消并等待实际收尾，不丢弃保存任务。

执行观察在工具体返回前保存，最终冻结结果通过同一 Runtime 登记归档。面板分别显示观察、最终结果、错误和未知缺口，并提供逐次鉴权的完整 JSON 分页。普通展示材料标记 `role-read-result`，从已验证官方 Local 后端取得的外置正文标记 `sdk-local-spill`；模型仅得到有界资料引用，读取片段消耗新的工具尝试。SDK 外置关联不能证明完整时保留缺口并阻止后继模型，不从展示 locator 获取文件授权。当前兼容性限于固定官方 spill-policy、Local 后端和已核对的原生工具装配。

后继调用、回合提交、角色切换与停止等待实际动作、最终通知和必要 Home 归档。补写复用原结果与操作关联，不重复执行工具；同一操作的并发保存任务独立保留。原生 idle 不等于已持久保存，停止还等待 SDK Session 的实际 flush 确认。强退后保留旧预留、观察与材料，缺少最终证据则明确未知；已保存回复不会重新生成。

成功回复通过同次 Home 提交保存完整经历、原绑定的本地展示准备和输入完成。重开查询已保存回复不重新生成；生成未保存的普通中断允许在原期限和剩余额度内重新推理，旧预留保留；运行中旧组若已进入文件修改，则保留效果与缺口并失败结案，不重建动作计划或自动重放。「本地已可查询」「当前视图已渲染」和「用户已读」分别表示不同事实。完整回复与执行记录只经逐次 owner 鉴权的有界分页接口读取。

创建先持久保存完整身份、核心和初始设定，再经宿主 configEditor 登记引导位置。登记失败保留资料，使用原路径、原 operationId 和原内容接续；浏览器保留在途请求并支持原操作查询。接入已有 Home 必须提供角色 ID，先校验格式、提交链、正文及独占写入权，不初始化覆盖。跨机器/路径副本须先停旧并完成单活交接；本地锁不能证明其他副本未运行。

迁移先在旧实例的「迁移交接」提交一份新的交接备份。系统等待真实动作、最终记录、模型 idle 和必要 Session flush，再保存独立交接事实、关闭旧 Home 并复制完整清单。旧实例普通重开保持只读；源进程中断后的旧 flush 若无法证明，会明确保留未知与原动作缺口，不重做工具或冒充已持久。普通历史备份和本地目录锁都不代替当前单活交接。

在空白 profile 的恢复入口提供完整备份目录、空目标 Home、原 RoleId 和清单 SHA-256。先校验并复制同一身份、核心、原始经历、知识、作品、待办、发件及用量，再保持只读供核对。目标已有 writer、非空用户资料、别名、物理身份变更或清单不符时拒绝覆盖。owner 必须明确确认旧环境当前已停止，才保存接受事实并完成本机登记；在途或结果不明时保留原 operationId、原 CAS、路径与摘要查询/接续，不换键或强行删除资料。

有 QQ 绑定时，先在目标 profile 映射本机连接与 credentialRef，通过实际机器人账号和原指定好友的只读核验；凭据值和 DSH 执行栈不复制。核验期间来信不接纳，也不发送旧发件。Home 权限簿可以保留外部 grant，但本机目录初始未绑定，旧绝对路径不自动授予访问。已核验的恢复源和 Home 仍受保护，父目录授权不能解除；缺失或不明的保护缓存不会初始化为空来恢复访问。

接受后旧 queued、未完成 Run、pending/unknown 和失效绑定保留原关联，不自动重推理、重发或转到新目标；改预览规则也不重新发行发送权限。未知发件只由 owner 核对后明确提交新的重发，仍须当前绑定有效。明确新来信才开始新的付费工作；已保存回复仅查询，不再生成。自主旧窗口、费用、休息和暂停保留，新 wake 不解除继承 Run 的禁止恢复资格。再次迁出当前实例要发起新的交接，历史 incoming 记录只供查询。

角色核心与设定只存入 Home 的版本化提交及受管正文；profile 只保存 Home 位置、身份核对和引导版本。手工文本投影改动保留并报告 diff，owner 可显式导入或重建。未知格式、损坏内容、活写者或不能证明已退出的锁会拒绝写打开；同一面板可提供有界只读诊断。
